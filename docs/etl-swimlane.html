🛡️ Garantias de Qualidade e Confiabilidade dos Dados

✅ Validação de CPF

  • Algoritmo módulo 11 aplicado em cada registro
  • Sequências inválidas (111.111.111-11) rejeitadas
  • CPFs rejeitados: logados com detalhe do erro
  • Usuário com CPF inválido não chega ao Keycloak
  • Visível em: steps[staging].records_error

🔗 Deduplicação por CPF

  • Mesmo usuário em SE1426, EOL e CoreSSO = 1 conta no KC
  • Prioridade: SE1426 (RH) > EOL > CoreSSO
  • Campos complementares mesclados entre fontes
  • Chave de dedup: CPF normalizado
  • Visível em: steps[crossref_dedup].records_out

♻️ Idempotência (evita re-envio)

  • Hash SHA-256 dos dados comparado a cada execução
  • Dados inalterados: ignorados sem re-envio ao KC
  • Registro em UpsertControl por usuário/realm
  • Falha no worker: pipeline reinicia do step que falhou
  • Re-execuções paralelas: bloqueadas por lock de execução

📋 Rastreabilidade Total

  • Cada execução tem log individual por step (ETLStepLog)
  • Contadores: extraídos, transformados, carregados, erros
  • error_detail por registro com dado inválido
  • Auditoria em UpsertControl: quando, o quê, qual ação (create/update)
  • Consulta: GET /api/executions/{id}/

🎮 Controle Granular — Validação e Carga Parcial

Para validação do PO: é possível carregar 1, 100 ou qualquer N usuários, ou um CPF/RF específico, sem precisar rodar o pipeline completo.

🔍 Verificar usuário por CPF (sem enviar ao KC)

POST /api/sync-selective/ { "cpfs": ["123.456.789-09"], "load_keycloak": false } → Mostra: nome, fonte, CPF validado, status

🚀 Enviar 1 usuário por CPF ao Keycloak

POST /api/sync-selective/ { "cpfs": ["123.456.789-09"], "load_keycloak": true, "realm": "sme-apps" } → Retorna: kc_action: created/updated

🧪 Carregar 100 usuários (piloto)

POST /api/executions/{id}/reload_keycloak/ { "max_records": 100, "reset_loaded": true } → Carrega exatamente 100 do staging

📦 Carregar 1.000 usuários (homologação)

POST /api/executions/{id}/reload_keycloak/ { "max_records": 1000, "reset_loaded": true } → Valide no KC antes do go-live

🔄 Re-executar step 3 (transform) isolado

POST /api/executions/{id}/run-transform/ { "force": true } → Reprocessa validação de CPF/RF/nome

📊 Ver métricas de qualidade da execução

GET /api/executions/{id}/ → steps[staging].records_error = CPFs inválidos → steps[crossref_dedup].records_out = após dedup → steps[load_keycloak].records_out = enviados
